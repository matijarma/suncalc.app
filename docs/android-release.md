# SunCalc on Google Play

The Android release is a bundled planner, package `app.suncalc.planner`. The hosted planner continues to use its existing preview and billing settings. Offline first open reads bundled assets and local trial state; the Android host initializes Google Play billing and synchronizes entitlements only after Android reports a validated network. Android 10+, target SDK 36. The release signing key stays outside Git.

## Build and test

From the repository root, run `npm ci`, then `cd android && ./gradlew testDebugUnitTest lintRelease assembleDebug assembleRelease bundleRelease`. The Gradle build compiles the Android-specific Vite entry and bundles maps, workers, search and fonts; never copy the hosted homepage into the APK. Run `npm run ci`, `npm run test:browser` and `npx playwright test --config android/playwright.config.ts` from the repository root. The Android UI tests exercise the shipped web bundle with a test-only native bridge.

For device tests, start an Android emulator or connect a test phone, enable airplane mode, then run `./gradlew connectedDebugAndroidTest` from `android`. These tests use the debug app’s own data and exercise the real WebView, message bridge, bundled town search, and the expiry gate. The reproducible store screenshots use the same shipped UI with a simulated position and compass heading (`CHROME_BIN=/usr/bin/google-chrome node scripts/android-screens.mjs` after building).

Signing uses `~/.config/suncalc/upload.properties` (or `SUNCALC_SIGNING_CONFIG`), a protected Java properties file with storeFile, storePassword, keyAlias and keyPassword. Back up the upload keystore and its credentials separately. Add `-PsunCalcVersionCode=N` for later uploads; never reuse a Play version code. Use Play App Signing. If Android terminates an initialized renderer, the app shows a native recovery screen; reopening preserves local places and the trial. A missing or unsupported system WebView displays an update prompt. The APK and AAB are under `android/app/build/outputs`. The direct APK signature is already in the website’s Digital Asset Links file. Add the **Play app signing certificate** as a second SHA-256 fingerprint when Play issues it; the upload certificate alone cannot verify a Play-installed copy. Test `adb shell pm get-app-links app.suncalc.planner` on that copy.

## First app record, products and server

1. In Play Console create **SunCalc: Sun & Shadow Planner**, English (en-US), app, free download, Tools. Upload the signed AAB to an internal draft. The Publishing API cannot create the first app record. Set all supported purchase markets for production.
2. Create subscription **suncalc_monthly**, title “Monthly planner”, with one auto-renewing base plan **monthly**, period P1M. Create one-time product **suncalc_lifetime**, title “Lifetime planner”, with a non-consumable **buy** option. No Play trial offer on either product: the app grants the first seven days without a payment method. Set euro markets to **€0.50** and **€5.00** respectively, use Play’s local conversion for other markets, review taxes/minimums, then activate both. Local prices always come from Play.
3. Enable Android Publisher API for a dedicated Google Cloud service account. Grant it access to this package only, including viewing financial data/orders and managing orders/subscriptions for verification and acknowledgement. Provide the service account JSON via Worker secret **PLAY_SERVICE_ACCOUNT**; never use another product’s private key or commit credentials.
4. Create a Pub/Sub topic, grant the Google Play notification publisher (`google-play-developer-notifications@system.gserviceaccount.com`) Pub/Sub Publisher, then enable subscription **and one-time** notifications in Play monetization settings. Configure an authenticated push subscription to `https://suncalc.app/api/android/notifications`. Give the Pub/Sub service agent permission to sign identity tokens for the push service account. Set **PLAY_PUSH_EMAIL** to that account email and **PLAY_PUSH_AUDIENCE** to the push endpoint. Send a Console test notification and verify delivery. Purchase buttons remain disabled until the Worker has all three billing settings and Play returns offers. Trial registration only needs **ANDROID_TRIAL_SECRET** and D1 migration 0002. Keep this trial key stable.
5. Supply the English listing, graphics and reviewer notes from `android/play`. Use the public [Android privacy policy](https://suncalc.app/android/privacy/). Declare the actual Data Safety behavior below. Supply the developer’s public support email, content rating, audience and merchant declarations in the Console. Do not represent the app as a children’s product or as collecting location in the background.

## Data Safety and test gates

The planner has no account, advertising, or analytics SDK. Location and compass readings for Live Shadow stay on device. Requests for unbundled map tiles reveal the viewport; submitted global address search text is sent to Geoapify. Declare relevant location and search categories for those network features. Declare pseudonymous device/installation identifiers and verified purchase history for trial, restoration and fraud prevention. Google Play processes payments; the developer does not collect card numbers. Transport uses HTTPS. The Android privacy policy explains retention and requests for deletion. Recheck the [Google Play Data Safety instructions](https://support.google.com/googleplay/android-developer/answer/10787469) against the actual release when filling the form.

On the internal track, use license testers and Play Billing Lab. Verify pending versus settled purchases, acknowledgement, paid access across devices and reinstall, cancellation until end of term, renewal, hold, grace, refund and revocation; repeat with the network disabled. Confirm foreground expiry, restoration of saved places, and that a refunded lifetime purchase loses access after reconnect. Check the public share links with the Play signature. Outdoors, compare the compass with a real vertical post, rotate the phone, then test no permission, unreliable heading and night. Follow any closed testing requirement shown for the developer account before requesting production access. Only submit the first worldwide production release after these checks.

## Operation

The Worker routes are POST /api/android/state, /api/android/verify and /api/android/notifications. The first two are native-only and HTTPS; the push endpoint verifies Google OIDC and refreshes entitlements from the Publisher API. The trial remembers a keyed device digest, while paid access is linked to an installation only after Play verification. The database stores purchase token digests, never the raw token. A verified lifetime purchase works offline; a subscription expires at the last verified entitlement boundary. An offline reinstall is provisional until the earliest registered trial start can be reconciled.

For production health, check Play Console Android vitals, Publisher API errors, Pub/Sub failed deliveries/oldest unacknowledged message and unacknowledged orders. No sensor, pin or token logging. Ship the Worker through the repository’s Git-connected Cloudflare build; do not change the web BILLING_MODE to launch Android.
